# Goal — One way in: home, search and a shell that joins the apps

Stated 2026-10-01. This is the plan's H goal: [`FOUNDRY_UI_PLAN`](FOUNDRY_UI_PLAN_2026-09-24.md)'s
wave 2, home and shell (H2–H16), with wave 0's H1 and the approvals inbox (A10) the plan parked
here. It follows [`GOAL_FOUNDATIONS`](GOAL_FOUNDATIONS_2026-09-25.md), whose A1–A6, A8 and A9 are
Met and whose A7 is Open only as the owner of `raw_colour_ceiling`.

Wave 1 built the tissue: every resource kind has a URL (A6), Dialog, Menu and Tooltip exist (A7),
Tabs exist (A8), and one registry lists the apps (A9). Nothing yet *uses* that tissue to join the
apps. A person still arrives at a flat list of 23 names, searches only those names, and sees two
bars above every screen that belong to one workflow. This goal is the first that changes what a
person meets on arrival.

Everything below was re-read against the code at `27cc953` on 2026-10-01. The fast tier passes
25 of 25 there, the tree is clean, and nothing has been pushed.

## What this is not

Not the Files app or project pages. Home's "Projects" toggle lists what `GET /tenancy/projects`
returns; the project model is decision O and wave 3.

Not a copy of the original's home. No training tracks, community, newsletter, "What's New" or
"Install examples": there is nothing behind them, and an entry with nothing behind it is inert.

Not a new search engine. The predicates move into SQL and the totals become true; ranking stays
what it is.

Not the builders' parity, the Workshop composer, or Object View. Those are the Y, W and O goals,
and each waits for its own statement. This goal's last condition to close names which comes next.
