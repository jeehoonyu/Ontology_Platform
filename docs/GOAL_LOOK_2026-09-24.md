## Design

**The table comes first, and screens change only through base rules and primitives.** Tokens,
the base element rules (button, input, select, headings, panel, pane, table, badge) and the
primitives restyle every screen through a few dozen lines. Per-screen CSS changes only when a
primitive replaces it or a change already touches it. This is not the rewrite GOAL_UI_ENHANCEMENT
J2 declined: nothing is migrated region by region for its own sake (decision I).

**A token that fixes a live bug comes before any token that changes a look.** Aliasing the seven
undefined names restores borders, grounds and active tabs that Decision and Ops have lost; it is
U3, before the font and before the body size.

**The gate must be able to see a thing before the thing lands.** The style audit counts before
any token is used (U1); the payload gate learns to weigh fonts before a font exists (U2).

**Values, not Blueprint, and not the brand.** We keep our own primitives and take the measured
values. The palette is Blueprint's open-source palette, the face an open-source font; logos,
illustrations and product names stay out.

**Titles stay headings, and test hooks stay.** Sixty-four heading-role locators, in eight spec
files, find titles by role. A
restyled Panel keeps `section.panel > header.panel-header > h2`; a restyled Page keeps exactly one
`h1`; pane titles stay `<strong>`. Classes the tests use (`.badge`, `.empty`, `.metric-card`,
`.workspace-header`, `.pane-header strong`) stay on the root element.

**Heights are minimums.** Some of our buttons wrap to two lines on purpose (Ontology Contracts
rows, the narrow pager, the two-line nav item). The control height is a `min-height`.

**One commit per step, and each is measured.** The font and the body size each move every glyph
on every screen, so each gets its own commit and a full six-project run against the numbers
recorded before any step.

**What is not here.** Shell width (GOAL_SHELL declared its layout out of scope; the plan's H7
and decision H carry it), graph geometry (the plan's Y6, after the stage fits the graph), dark
dashboards (no runtime surface exists until the plan's W3; the dark tokens wait for W17), and the
icon rail (the original's rail switches tool views, which is function: the plan's Y13).

- **U1 — The style table is counted before any of it is used.** **Met** —
  `oms/audit_style_tokens.py` generates `docs/STYLE_TOKENS.md`, `docs/style-tokens-baseline.json`
  (the undefined counts) and `docs/raw-colours-baseline.json` (the colour ceiling), is declared in
  `check_registry.py` and `enforcement_runs.py`, and joins `verify.py --fast` (now 25 checks).
  Its first run recorded 7 undefined names, 39 undefined references and a `raw_colour_ceiling` of
  661 (632 in `styles.css`: 607 hex and 25 `rgb()`/`rgba()`; 29 in TSX strings across five files).
  Proven by `oms/test_style_tokens_audit.py` (48 assertions).

  **What was built.** Two gated counts and two gated shapes. A custom property is undefined when a
  `var()` in our live stylesheets or TS strings names something no *imported* stylesheet defines
  and no component sets inline (`Pane.tsx:332` sets `--slot-width`, which therefore counts as
  defined); a reference with a fallback renders it and is reported, not counted. A raw colour is a
  3-, 4-, 6- or 8-digit hex or an `rgb()`/`rgba()`/`hsl()`/`hsla()` in a stylesheet declaration
  value or a TS string literal, outside `tokens.css`, never in a comment, a selector or `url(#…)`.
  `tokens.css` may hold custom properties on `:root` and nothing else, because
  `audit_style_scope` reads `styles.css` alone and could not see a class written there. The
  reference is regenerated with `--write` and fails when it disagrees with the source. Radius and
  height literals (111 in 12 values; 90), the 39 legacy alias uses and the 396 tokens not yet in
  effect are reported, not gated. Colours the server sends are not counted: the pipeline legend
  (`oms/app/pipeline_builder_ops.py:672-677`, `#7d8b99` and `#1388b8`, which already disagree with
  the CSS bands `#8c9aa6` and `#1586b4` at `styles.css:3057-3063`) is the plan's Y6 and Y12 to
  replace.

  **Why two baseline files.** U3 takes the undefined counts to zero without touching a colour.
  One file holding both would record the colour ceiling a second time at the same value, which
  `audit_ratchet_motion` reads from the file's history as a ratchet recorded and never lowered.
  So the colour ceiling has its own file, and `--set-baseline` rewrites a file only when one of
  its numbers moved; a second run reports "rewrote nothing".

  `frontend/src`. `tokens.css` already defines all seven missing names in its alias block, and
  nothing imports it, so that draft read 0 undefined names on a tree where all 39 declarations are
  still dropped. Only imported sheets define anything now, and the first synthetic case exists to
  hold that line.

## What this is not

Not Blueprint: the original ships Blueprint's components; ours keeps its own primitives and
takes the values. Not a copy of the brand. Not the shell's width, the graph's geometry or the
dashboards' dark ground: those need function first and are ordered in the plan. And not a claim
that the look is done when the tokens land: U1–U5 make it consistent; U6–U10 make it similar; the
plan's surfaces are where the rest of the distance is.
