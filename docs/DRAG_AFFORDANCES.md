# Drag interactions, and how to do them without dragging

Generated by `oms/audit_drag_affordances.py`. Do not edit by hand — the gate
regenerates this and fails if it disagrees with the source.

Native HTML5 drag-and-drop does not fire from touch input and is not operable
from the keyboard. That is a property of the platform, not of this code. Every
HTML5 drag below therefore carries a second control that does the same thing,
and a browser test that operates that control with a finger.

| Drag | Moves | Without a drag | Proven by |
| --- | --- | --- | --- |
| `workspaces/OntologyManager.tsx` — setDragName | a property row above or below its neighbours, to reorder the schema | the `Up` and `Down` buttons on every row | a property row reorders without a drag |
| `workspaces/OntologyManager.tsx` — setDraggedField | a source dataset field onto an ontology property, to map one to the other | the `Map <property>` select beside every target property, which lists the same source fields | a source field maps onto a property without a drag |
| `workspaces/PipelineBuilder.tsx` — application/x-node-type | a node type from the palette onto the pipeline canvas | tapping the palette entry arms the type, and the empty canvas offers `Add <type>`; once nodes exist, the edge insert control does it | a touch user can add the first node to a pipeline |
| `workspaces/VisualBuilder.tsx` — application/ontology-builder-node | a node type from the library onto the artifact canvas | the library entry is a button; tapping it calls `addNode` and places the node without any pointer travel | a library node reaches the canvas without a drag |

## Drags a sensor library carries

No alternative control, because the sensor is meant to handle touch itself. That is a
claim about the library, and it was true here while the screen was still unusable: the
grip carried no `touch-action: none`, so the browser spent every gesture on scrolling
before the pointer sensor saw a move. Each one below is dragged by a real touch point
in a browser test.

| File | Moves | Sensor | Proven by |
| --- | --- | --- | --- |
| `workspaces/VisualBuilder.tsx` | a configuration field above or below its neighbours in the node inspector | @dnd-kit `useSortable`, pointer and keyboard sensors | the sortable field list reorders from touch |

## Mechanisms in use

| Mechanism | Where | Reachable without a mouse |
| --- | --- | --- |
| native HTML5 | 4 sources in 3 files | never — by a second control only |
| `@dnd-kit` | `workspaces/VisualBuilder.tsx` | yes, measured by touch |
| `@xyflow/react` | `workspaces/OntologyManager.tsx`, `workspaces/PlatformGraph.tsx`, `workspaces/VisualBuilder.tsx` | pan and zoom, not node placement |
